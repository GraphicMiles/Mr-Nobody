How an answer is drawn now

The model still writes Markdown. The chat never shows that source. A parser turns it into heading, emphasis, lists and cards — then the source row sits at 80% opacity so it stays attributed without taking over.

Pipeline
01

Read pages

Search, then fetch. Each page’s og:image is kept with the shortlist.

02

Download stills

Up to 3 previews come through NetworkGate into the workspace — not a raw CDN call from Flutter.

03

Write the answer

The model is asked for a # heading, **bold** facts, short paragraphs, [n] cites.

04

Parse, don’t dump

AnswerDocument strips asterisks, builds blocks, binds [1] to a real source.

05

Paint the turn

Trace stays collapsed. Body is typography. Cards sit under it. Sources fade to 0.8.

What is not shown

No **asterisks**. No raw URLs in the body. No tool dump. The trace is still there — collapsed — so the work is retrievable, not the face of the answer.

Where the pictures come from

Only pages the agent already read. og:image is pulled from that HTML, fetched through the same privacy route, and painted from a local file. A monogram is the fallback, never a stock photo.
