What the alignment fix actually is

The avatar was 26px with margin-top:1px, sitting beside a first line box of 13px × 1.62 = 21px. A 26px square next to a 21px line can only be centred on that line by accident, so it rode about 5px high and the whole agent turn looked like it was sagging away from its mark.

Now the avatar is a 21px box — exactly one line box — with a 19px mark centred inside it. Both are variables (--line-box, --avatar, --mark) derived from the type, so changing the body size moves them together rather than silently breaking the alignment again. In Flutter this is a SizedBox(height: 21, width: 21) with the logo centred, in a Row(crossAxisAlignment: .start).

gutter 16px both sides
avatar → text 10px
between turns 20px
block → stamp 5px
paragraph gap 9px

Every vertical gap now comes from one of those five numbers. Before, spacing was set per-element with padding:5px 16px on messages plus ad-hoc height:8px spacers, which is why the rhythm drifted down the column. A stamp under an agent turn is indented to 21 + 10 = 31px so it lines up with the text it belongs to, not the avatar.

The three states, and why they look different

  • Analysing — shimmer on the label, spinner on the live row, checks on the finished ones. The elapsed timer is the only number moving.
  • Streaming — trace collapses to one line the instant the first token lands. Two things animating at once reads as busy; the trace has had its turn.
  • Settled — Thought for 4 seconds, past tense, shimmer off, chevron closed. Then a hairline, then the controls. The warning sits above the divider because it belongs to the claim, not to the buttons.
Still true: the blur-in stream is animation over a finished string. AiProvider.complete() returns one payload and both remote providers buffer the whole body. Revealing it word-by-word on a timer is honest motion, not a live token feed, and it becomes genuinely live when the provider work lands — with no change to any of this.
