Three modes. One rule: fail closed.

Pick how much the browser remembers, and how traffic is routed. When a promised privacy route is unavailable, Mr Nobody refuses to silently fall back.

Normal

Standard browsing through your current network connection. No history saved by default.

Private

Reduced local retention with stronger isolation when the installed WebView supports it.

Nobody

Uses your configured privacy route: Orbot when available, otherwise bundled Tor. Fails closed rather than leaking.

Honest by design: privacy is not the same as anonymity. The interface reports effective protection instead of promising more than the device can deliver.

Questions? We have answers.

What exactly is Mr Nobody?

An open-source Android browser with an on-device agent for research, page reading, comparisons and authorised downloads. The browser and the agent share the same privacy controls, download system and network routing.

Does it need an account?

No. There is no account, no sign-in and no profile. Install it and it works.

What leaves my device?

By default, very little: pages you choose to open go to those sites, and update checks send lightweight version metadata. Clock, arithmetic and direct-action requests are answered locally by a fast path. A remote AI provider (Gemini, Groq or OpenAI-compatible) is used only if you enable one — and only the task context it needs leaves the device then.

Does it block ads and trackers?

Yes, locally. Known advertising and tracking requests are blocked on device, cross-site redirects to known gambling, pop-up and ad-heavy link-shortener destinations are stopped, tracking parameters are stripped from links, and history, third-party cookies and mixed content are off by default.

Are updates ever forced?

Never. The endpoint serves metadata only and the app never auto-downloads or executes anything. You see the version, release notes and integrity data, then choose — and “Remind me later” suppresses that release until a newer one appears.

What happens when I am offline?

Browsing continues normally. The last successful update check is cached on device, so an offline launch shows the last known state and an unreachable server never blocks the browser.

Can it open plain http pages?

Only after an explicit “Load anyway” warning, and the host is remembered for the session. Insecure downloads show a Continue / Reject warning before anything is fetched. The agent's autonomous tools still require HTTPS, so cleartext is never used outside your explicit choice.

Is it really open source?

Yes — MIT licensed on GitHub, with the main branch green in CI: 1,028 Java tests, 185 Flutter tests and 14 privacy-auditor tests run on every push, plus a strict signed-APK build gate.

What is the ⓘ debug panel in the release?

While the page-turns-black-after-load bug is under investigation, release builds carry the ⓘ panel. It shows the tab/WebView lifecycle trace (page start, progress, finish, attach/detach, renderer events), the error log, one-tap copy, and a surface-rebuild action. It is the only channel a user has to report exactly what happened on a real device, and it will be removed from public builds once the defect is fixed.
